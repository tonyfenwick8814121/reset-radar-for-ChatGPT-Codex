# 已重置通知与预告的区分

| 用户看到的状态 | 进入条件 | 窗口与提醒 | 用户操作与退出 |
|---|---|---|---|
| 重置预告 | 可信明确承诺；精确时间需要日期及时区 | 提前提醒，有明确时间才倒计时 | 可忽略；到点后等待确认 |
| 重置已完成 | 明确可信完成公告，发布于过去24小时内 | 完成标志与公告时间，不显示倒计时；首次显示窗口、按设置响铃、系统横幅 | “知道了”立即收起；公告发布24小时后归档 |
| 已忽略/已使用 | 用户已处理对应事件 | 不再显示或响铃；同次后续完成消息不恢复它 | 历史仍保留 |
| 旧公告/已归档 | 公告超过24小时，或已结束保留期 | 不发送完成通知 | 保留历史和已提醒身份，防止回放复活 |

识别、显示和完成通知共用可信完成门槛；模糊投票、问句、否定和“正在处理”不能越过门槛。公告完成不等于已读取或验证个人账号额度。缺少发布时间时不通知。

同一次预告、完成以及明确的传播确认使用一个事件身份。已提醒时间在通知前写入本地存储，跨来源重复、重查、重启和规则升级不重发。新一次明确完成仍独立提醒。遇到本地写入错误沿用应用的数据错误提示；系统通知权限关闭时，自动弹窗与用户启用的声音仍可工作。

完成通知可以临时显示完成事件；同时或随后发现新的预告时切回预告，不吞掉新机会。关闭或最小化窗口不会重新触发提示音。升级对24小时内从未提醒的完成公告补发一次，旧公告静默。

验证覆盖：真实10月7日原帖、各完成表达及反例、只触发完成回调、跨来源/多帖合并、重复查询、重启持久化、规则升级、忽略后的传播消息、另一次独立重置、新预告、24小时归档；原生主/迷你窗中英文与按钮做发布烟测。
